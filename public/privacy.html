Privacy Policy

Last updated: 27 November 2026

The short version. The core editor is local by default and does not require an account. Your current draft, locally saved messages, recent webhook URLs, attachments, preferences, and any AI API keys are kept in your browser. Apart from analytics, crash reports and normal web requests, what you create leaves your device when you use a feature that needs it: sending, short links, schedules, server libraries, the Discord Activity, avatar uploads, AI, plugins, feedback, or connecting an AI app. When you're signed in, sending to a server also uploads the message and webhook URL to us for that server's history. Built-in AI sends your prompt and current message through our server to Groq. Signing in and paid plans share the account details described below. After you send a message, the confirmation may show an offer for DWEEB's own paid plans or, if third-party ads are switched on, one non-personalized ad from Google instead. Neither is shown when DWEEB knows the server is on a paid plan. We do not sell your data.

This policy explains what DWEEB (the "Discord Webhook Embed Builder," "we," "us"), hosted at dweeb.faizo.net, does with information when you use the site. DWEEB is free for noncommercial use and source-available; the source code is available at github.com/FaizoKen/DWEEB.

1. Local-by-default editor data

The core DWEEB editor is a client-side application. The following are saved to your browser's localStorage / IndexedDB and are not sent to our servers merely by editing:

  • The message you're currently editing (auto-saved draft).
  • Webhook URLs you enter and your list of recently used webhooks.
  • Messages you explicitly save as Browser drafts.
  • Attachments/images you add while building, until you send or upload them.
  • API keys you add to use your own AI provider. Built-in AI doesn't need one.
  • Interface preferences (e.g. the last server you connected to).

This data stays on your device until you remove it. You can clear it at any time by clearing your browser's site data for dweeb.faizo.net, or by using the in-app controls (Reset, remove a saved webhook, etc.).

Choosing an action can transmit the relevant data. For example, Send uploads the message and attachments to Discord and may record the message with us, built-in AI sends your prompt and message through our server, and a server draft uploads the message to DWEEB's server library. The sections below describe each case.

Plugins. A plugin configuration iframe may request only the editor resources declared in its bundled manifest. Saved-webhook lists contain labels, not tokens. If a plugin needs a webhook credential, DWEEB names the plugin and destination and asks you before sharing that one URL. A stateful plugin retains an approved URL in its own configuration so it can keep handling interactions. Removing the component or clearing browser data does not delete that server-side plugin record. DWEEB's bundled plugins store their configurations, which can include message content, form questions and webhook URLs, in databases on our server. Delete or replace the webhook in Discord to revoke a stored URL. Plugin configuration and interaction services process the other data needed for the action, so attach and configure only plugins you trust.

With a server connected, the plugin library and link-plugin panels ask that plugin's operator, such as RoleLogic, whether it is set up. That request carries the server's ID and normal web-request information, but no cookies or message content.

2. Share links

When you create a share link, the entire message is compressed into the URL's # hash fragment (for example dweeb.faizo.net/#s=…). By design, browsers never send the fragment to a web server, so the contents of a share link are not received or stored by us. However, anyone you give the link to can open and read that message, so treat share links accordingly.

Short links (optional). If you choose to create a short link, the compressed message is uploaded to our server and stored under a random id so it can be served from a short dweeb.faizo.net/s/… URL. Unlike the hash link above, this means the message contents do reach us. Short links automatically expire and are deleted after 7 days. The short-link record itself contains no account or IP-address field; ordinary infrastructure and security logs may still process request metadata as described below. Don't create one for a message you wouldn't want on our server — use the default hash link instead.

DWEEB creates a short link by itself in two cases where a message is too large for a normal link: Open on web in the Discord Activity, and DWEEB's message commands in Discord.

3. Sending messages to Discord

In the web app, clicking Send, Restore, or update normally makes your browser talk directly to Discord's webhook API. Your webhook URL, message content, and any uploaded files go to Discord. Activity publishing, scheduled posts and posts from a connected AI app instead pass through our server. So do webhook URLs that DWEEB looks up or creates for a server you connect. Discord's handling is governed by Discord's Privacy Policy. A webhook URL is a credential — treat it like a password and only share it with people you trust.

Posted history. If you're signed in, after a successful send or update to a server your browser also sends the message, webhook URL and destination to our server for that server's Posted history. We store it only if you can manage that server's webhooks. Otherwise we refuse it without storing or logging its contents. If you aren't signed in, your browser doesn't send it.

Message commands in Discord. When someone uses one of DWEEB's commands on a message, Discord sends us that message and who used the command so we can reply. We don't store the message unless the reply needs a short link, as described above.

Messages can contain image, video, and other media URLs. Opening a preview or shared design may cause the viewer's browser to request that media from its host, which can receive normal web-request information such as the viewer's IP address and browser details.

4. Signing in with Discord (optional)

If you choose to sign in, we use Discord's OAuth flow and receive your Discord user ID, username or display name, avatar, an access token, and the list of servers you're in, with your permissions in each. Your ID, name, avatar and token are kept in an encrypted, HttpOnly session cookie that normally lasts up to 7 days. We use the token to identify you and check which servers you can use. Server lists and data are briefly cached on our server to reduce calls to Discord. The Discord Activity uses a token from Discord in the same way, without that cookie.

We don't keep account profiles, but features you use can store your Discord ID, as described in this policy. Signing out clears the session cookie. It doesn't delete those records or disconnect an AI app.

5. Server-backed features (optional)

These features store or relay data because they cannot work solely in one browser:

  • Scheduled posts. We store the Discord webhook URL, message payload, schedule, destination identifiers, and ownership/management data. Sensitive payloads and webhook URLs are sealed at rest. Active schedules, including paused and repeating ones, remain until they finish or are cancelled; completed and failed rows are normally removed after 7 days.
  • Server message library. Server drafts and a rolling history of messages posted through DWEEB store the message, its destination, the Discord ID of the person who saved or posted it and, where needed for later editing, the webhook URL. Messages and webhook URLs are sealed at rest. Drafts remain until deleted. Once posted history reaches the server's plan limit, each new post deletes its oldest entry; entries for never-expire messages are always kept. If the limit drops, entries over it are hidden, not deleted, until it rises again. We check with Discord whether posted messages still exist and keep history of deleted ones for 30 days. People who can manage that server's webhooks can access its library.
  • Discord Activity. Collaborative room state and presence are relayed in real time. Recoverable Activity drafts are stored server-side and normally expire after 7 days without activity. Publishing and editing are proxied to Discord and may be recorded in the server's posted-message history.
  • Support tickets (Tickets plugin). In a server that uses DWEEB's Tickets plugin, the DWEEB bot creates a private channel for each ticket. The plugin stores the panel's settings (staff roles, categories, log channel and form questions) and a record of each ticket: the server and channel IDs, the ticket number and topic, the Discord user ID and name of the member who opened it, who claimed and closed it, and when. Answers to a ticket's intake form are posted into the ticket channel, not stored by the plugin. Transcripts are a per-panel setting that the server's managers control; it is on by default once they choose a log channel, and they can turn it off. While it is on, closing a ticket makes the bot read that ticket channel's messages once — at most the 500 most recent — through Discord's API, including their text, attachment links and embeds (Discord's message content), and turn them into an HTML transcript. The transcript is posted to the log channel the server's managers chose and, if they enabled it, sent by direct message to the member who opened the ticket. It is built in memory and kept only as that Discord attachment: DWEEB does not store the message content it reads, log it, use it for analytics or advertising, share it with anyone else, or use it to train machine-learning or AI models. Anyone who can read the log channel can read its transcripts, so write in a ticket as you would in any channel the server's staff can see.
  • Other bundled plugins. Besides their configurations, Giveaway stores entrants' and winners' Discord IDs, Poll stores each voter's ID and choices, Modal Form stores who submitted when a form allows one response, and Self Role stores temporary role grants until they expire. Form answers are processed and forwarded to the destination the form's creator chose, not stored by the plugin.
  • Never-expire messages and custom bots. For a never-expire message we store its message, channel and server IDs and who added it. For a custom bot we store its name, application ID, public key, who added it, and any client secret or webhook URL in encrypted form. To run component expiry, we also record when a message's buttons or menus were last used, without who used them.
  • Avatar uploads. An avatar you upload is resized in your browser, then stored on our server indefinitely at a public URL, because Discord loads it every time it shows the message. The image record doesn't include your Discord ID.
  • Ratings. If you rate DWEEB, we store your Discord ID, score and when you rated. Only the combined score and count are published.
  • Connected AI apps (MCP). If you authorize an app such as Claude, we store its registration and, for up to 7 days, your Discord ID and encrypted Discord access token so it can act as you in DWEEB. The app receives what it requests, such as your servers, their channels and messages posted through DWEEB, and handles it under its own privacy policy. You can end access sooner by removing DWEEB under Discord's Authorized Apps.
  • Feedback. When you submit the feedback form, we receive the category, summary, details, and optional contact you enter. Normal proxy logs may also contain request metadata such as an IP address and browser user agent. The report is relayed to our feedback forum and retained there so maintainers and community members with access to that forum can respond and help improve DWEEB. When you submit from the Discord Activity, the report also includes your verified Discord display name and user ID. Do not include secrets.
  • Plans and billing. Stripe processes checkout and payment details. We send Stripe your Discord user ID and display name and the server's ID, and keep a subscription mirror containing the identifiers and status needed to bind a plan to a server and enforce its quotas. RoleLogic, also operated by Faizo, uses the same Stripe account, so it can read those subscription details to honor the plan there. DWEEB does not receive or store full card details.

6. The AI assistant (optional)

The assistant works in two ways, and they handle your data differently.

Built-in DWEEB AI (the default)

  • What is sent. When you use it, your browser sends our server your prompt, recent chat (up to 12 turns, including the AI's replies) and the message in the editor, including its webhook name, avatar URL, text and links. It also sends the connected server's ID and your sign-in. DWEEB may send a follow-up request automatically to repair a reply. Uploaded files and the webhook URL you send through aren't included, but anything you type into the message or chat is.
  • Who receives it. Our server passes the prompt, chat and message to Groq, which runs the model. We don't send Groq your Discord ID, server ID, sign-in token or IP address. Anything personal you write in the text is still sent.
  • What Groq keeps. Groq may store inputs and replies for up to 30 days for reliability, abuse and compliance purposes, or longer where the law requires it. It stores them in the United States and may process them in other countries. Its agreement doesn't let it train models on them unless we permit it, and we don't. See Groq's data practices and services agreement.
  • What we keep. We don't store your prompts, chat or the AI's replies, or use them for analytics, advertising or training. We store a daily count of your requests and tokens under your Discord ID for about 35 days. Our server logs record your Discord ID, the connected server's ID, plan, model, token counts and timing for each request. If Groq returns an error, we also log the start of its error response.

Your own provider

If you choose your own provider instead, such as OpenAI, Anthropic, Google, Groq, OpenRouter, a compatible endpoint or Ollama, your prompt, chat, current message and any API key go directly from your browser to that provider. They don't pass through our server. That provider's privacy policy and terms apply, and a custom endpoint is controlled by whoever operates it.

In both cases the chat is kept only in the open tab's memory. An API key is saved in your browser's storage until you remove it.

7. Analytics and advertising

We use Google Analytics to understand how DWEEB is used (for example, how many people visit and which features are popular). Google Analytics may collect information such as the pages you view, your approximate location derived from your IP address, and your device and browser type, and may set cookies. This is governed by Google's Privacy Policy. DWEEB sends a page's public canonical URL rather than the live address bar (keeping only a tag that names the AI assistant whose link you followed, such as ChatGPT), reduces a referring URL to its site origin, and limits product events to fixed public fields. Draft hashes, webhook and OAuth values, Discord identifiers, and message text are not analytics fields. DWEEB does not load Google Analytics when your browser sends Do Not Track or Global Privacy Control. You can also opt out using the Google Analytics opt-out browser add-on or a content blocker.

DWEEB's own offer. After you send a message from the web app, the confirmation that it was posted may show an offer for DWEEB's paid plans. It is our own: no ad network is involved and it loads nothing from a third party. Google Analytics, as described above, records only that it was shown, opened or dismissed. To decide whether to show it, DWEEB asks its own server for that Discord server's plan, and keeps a send count and when the offer was last shown or dismissed in your browser.

Advertising. DWEEB can show a third-party advertisement in that same place instead of its own offer. When that is switched on, the confirmation may show one advertisement, served by Google AdSense. That is the only place DWEEB shows an ad: never in the editor, the guides or templates, or the Discord Activity; never for a message sent to a server on a paid plan (Plus or Pro); not on your first send; and not when your browser sends Do Not Track or Global Privacy Control or asks to save data. DWEEB requests non-personalized ads and tells Google's tags that consent to advertising storage and ad personalization is denied, so the ad is chosen from the page's context, not from a profile of you. To deliver and measure the ad and to prevent fraud, Google receives the information any web request carries — such as your IP address, browser details and the page address (dweeb.faizo.net) — and may use limited identifiers for frequency capping and fraud prevention. DWEEB never gives the ad network your message content, webhook URLs, Discord identifiers or server names, and it skips the ad whenever the address bar still holds app state. See how Google uses information from sites that use its services. A content blocker stops the ad from loading, and DWEEB works the same without it.

8. Crash reports (diagnostics)

Because DWEEB's editor UI runs in your browser, a bug that breaks it is otherwise invisible to us. When an unexpected runtime error occurs, DWEEB sends a small, automatic crash report to our server so we can find and fix it. A report contains the type of error, its message and a few lines of the code stack trace, the app's version and build, which surface you were using, and the page path (for example /templates). It does not attach your message, account, webhook URL, API key or the # hash fragment, although an error message can occasionally quote part of the value that caused it. Reports are rate-limited and written to our server logs, and serious ones are forwarded to a private maintainer channel on Discord. They aren't separately opt-in. DWEEB suppresses them when your browser sends Do Not Track or Global Privacy Control; a content blocker can suppress them too.

The Discord Activity also reports how its launch went: the step, outcome, timing, platform, Activity instance ID and, on failure, the error.

9. Hosting and server logs

The website is hosted on GitHub Pages. Our server, its databases and the bundled plugins run on a server rented from Contabo. Both process technical data such as IP addresses to deliver the service. We also use IP addresses to rate-limit and protect against abuse.

Our server logs can contain Discord user, server, channel and message IDs, and error entries can contain IP addresses, browser details and request addresses. Logs are deleted as they rotate, currently after about six weeks, though this can vary with volume. Error entries may be forwarded to a private maintainer channel on Discord, where they can remain longer. We don't use any of this to build advertising or behavioral profiles.

10. Cookies

  • Session cookie — set only when you sign in with Discord (encrypted, HttpOnly), plus a short-lived OAuth state cookie for security. Cleared on sign-out.
  • Analytics cookies — set by Google Analytics, as described above.
  • Payment cookies — set by Stripe, for payment and fraud prevention, only once you start checkout or open billing.
  • Ad delivery — when an ad is shown after a send, Google AdSense may use limited, non-personalizing storage for frequency capping and fraud prevention.

We do not use cookies for personalized advertising or cross-site tracking.

12. Data retention

Local data persists until you remove it or clear this site's browser storage. Short links expire after 7 days. Activity drafts normally expire after 7 inactive days. Completed or failed schedules are normally swept after 7 days; active schedules remain until completion or cancellation. Server-library drafts remain until deleted, while posted history rolls as described in section 5, with history of messages deleted on Discord kept for 30 days. Stateful plugin configuration, giveaway entries, poll votes and one-response records remain in that plugin service until removed by a user action or its operator; DWEEB currently has no automatic plugin-record deletion when you remove a component. Revoking the Discord webhook immediately makes a retained URL unusable. Ticket records stay in the Tickets service, which uses them to number tickets and apply a panel's limits, until its operator removes them; ticket transcripts exist only as Discord attachments and are deleted the way any Discord message is.

AI usage counts are deleted after about 35 days. A connected AI app's access expires within 7 days, and its unused registration is removed after about 30. Component-use times are removed once they can no longer affect expiry. Never-expire and custom-bot records remain until removed. Avatar uploads and ratings are kept until you ask us to delete them. Subscription records are retained as needed to administer plans, resolve disputes, and meet legal obligations. Feedback is kept as long as it is useful for improving DWEEB, and server logs as described in section 9. Our hosting provider's backups can hold copies of deleted data until those backups are replaced.

13. Children

DWEEB is not directed to children. You must meet Discord's minimum age requirement (at least 13, or older where your local law requires) to use Discord-related features.

14. Your rights

Depending on where you live (e.g. under the GDPR or CCPA), you may have rights to access, correct, or delete personal data. In practice, most of your data is local and already under your control: clear your browser's site data to erase it, sign out to clear the session cookie, cancel schedules, and delete server-library entries with the in-app controls. For anything else held on our side, or to make a request, contact us using the details below.

15. Changes to this policy

We may update this policy from time to time. Material changes will be reflected by updating the "Last updated" date above. Continued use of DWEEB after a change means you accept the revised policy.
